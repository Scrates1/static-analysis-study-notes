# 简单-如何使用YASA寻找代码中的空函数

首先，你需要新建一个checker继承自checker基类，并在构造函数中指定checkerId，同时传resultManager用于承载finding

[[CARD_01]]
```javascript
class EmptyFunctionBodyChecker extends Checker{
constructor(resultManager){
super(resultManager, 'EmptyFunctionBodyChecker')
}
}
```
第二步，根据需求，判断函数是不是空，那么在函数定义的checkpoint进行check，在checker中，使用trigger挂载checkpoint

[[CARD_02]]
```javascript
triggerAtFunctionDefinition(analyzer, scope, node, state, info) {
if (!node || !node.name) return
if (!node.body) return
if (node.body.body.length === 0) {
const finding = {...} //找到空函数后，制作你自己的finding结构，进行记录
this.resultManager.newFinding(finding,EmptyFunctionBodyStrategy.outputStrategyId) //outputStrategyId 需要指定，见下文
}

}
```

第三步，现在我们记录了finding，还需要指定如何打印finding，YASA将如何记录finding、打印finding的权利都交给了用户，可以灵活的打印自己需要的格式。我们需要实现一个strategy，放在src/checker/common/output 目录下，继承自OutputStrategy
接下来我们在strategy中定义outputFindings函数，YASA将在分析结束后调用这个函数对你的finding进行个性化的输出。

[[CARD_03]]
```javascript
class EmptyFunctionBodyStrategy extends OutputStrategy{

static outputStrategyId = 'EmptyFunctionBodyStrategy'

constructor() {
super()
this.outputFilePath = 'report.txt'
}

outputFindings(resultManager, outputFilePath, config, printf){
const allFindings = resultManager.getFindings()
const finding = allFindings[EmptyFunctionBodyStrategy.outputStrategyId]
console.log(finding)
//可以用outputFilePath输出到文件等
const reportFilePath = pathMod.join(Config.reportDir, outputFilePath)
FileUtil.writeJSONfile(reportFilePath, finding)
}
}
```
最后，你需要将你的checker注册到YASA上，注册方式在resource/checker/checker-config.json中，如下。由于这个checker不需要外部的输入，就不需要指定demoRuleConfigPath了。

[[CARD_04]]
```json
{
"checkerId": "EmptyFunctionBodyChecker",
"checkerPath": "src/checker/emptyFunctionBodyChecker.js",
"description": "寻找代码中的空函数",
}
```
注册好后，就可以通过--checkerIds来指定这个checker运行了，也可以制作一个规则包，将这个checker放进去和其他checker一起运行，注册到resource/checker/checker-pack-config.json中，就可以通过--checkerPackIds来指定这个规则包了
