# 第一部分：指针分析

## 1. 为什么间接内存访问是基础难题

考虑：

```c
int a, b;
int *p = &a;
int *q = p;
*q = 7;
```

源码中最后一行没有直接出现 `a`，但运行时它修改的是 `a`。如果分析器不知道 `q` 可能指向哪里，就无法可靠回答：

- `a` 在该点之后可能是什么值；
- `p` 与 `q` 是否访问同一位置；
- 写入是否污染了另一个变量；
- 某个 `free` 是否释放了仍被引用的对象；
- 虚调用可能分派到哪些目标；
- 两次内存访问能否重排。

现实程序中的栈对象、堆分配、全局变量、数组、结构体字段、对象成员和函数指针都可能经由间接访问。因此，指针分析通常是调用图、数据流、污点、并发和优化分析的前置能力。

## 2. 内存对象与 points-to 集合

### 2.1 先定义抽象对象

静态分析不能为每次动态分配都创建无限多个节点，通常把具体位置映射为**抽象对象**。常见策略包括：

- 每个全局变量一个对象；
- 每个栈变量一个对象，必要时再按调用上下文区分；
- 每个分配点（allocation site）一个堆对象；
- 字段敏感时，每个对象的字段 `o.f` 是独立对象；
- 数组可整体汇总，也可区分常量下标或某些分区。

记抽象对象全集为 \(Obj^\#\)，指针值节点集合为 \(Ptr\)。

### 2.2 points-to 关系

分析结果是映射：

\[
pts: Ptr\to\mathcal P(Obj^\#)
\]

\(o\in pts(p)\) 表示：在分析采用的程序点、上下文和路径抽象下，指针 `p` **可能**指向抽象对象 \(o\)。

对开头示例：

\[
pts(p)=pts(q)=\{o_a\}
\]

这里应说“抽象内存对象集合”，而不只是“地址被取过的变量集合”：堆分配点、字段、字符串常量和函数也可能成为对象。

## 3. points-to 与 alias 不是同一个问题

### 3.1 may-alias

若两个 points-to 集合有交集：

\[
pts(p)\cap pts(q)\ne\varnothing
\]

分析器通常回答 `p` 与 `q` **may alias**，即存在候选共同对象。若 points-to 是 sound 的过近似，这个条件对排除别名很有用：

\[
pts(p)\cap pts(q)=\varnothing
\implies p,q\text{ 在该抽象范围内不可能别名}
\]

但交集非空不保证存在一条真实执行让二者同时指向该对象。交集可能来自不可行路径、上下文合并或汇总对象，因此 may-alias 结果可有误报。

### 3.2 must-alias

must-alias 问的是：在关注的所有执行中，两个表达式是否必然表示同一具体位置。一个常见但带条件的充分判据是：

\[
pts(p)=pts(q)=\{o\}
\]

且 \(o\) 对应唯一具体位置、两者同时有效且不存在 null/生命周期歧义。若 \(o\) 是“某分配点产生的所有动态对象”的汇总节点，即使集合都是单元素，也不能直接推出两个指针必然指向同一次分配实例。

因此：

- points-to 分析产生集合事实；
- alias analysis 用这些事实回答两个访问之间的关系；
- 二者联系紧密，但不是严格同义词。

### 3.3 为什么别名影响优化和安全分析

```c
*p = 1;
x = *q;
```

- 若能证明 `p`、`q` must-alias，且中间没有其他写入，则可推出 `x == 1`；
- 若只能得到 may-alias，则 `x` 可能受该写入影响，不能做同样的常量替换；
- 在污点分析中，对 `*p` 的写可能流向 `*q` 的读；
- 在释放、越界和竞态分析中，漏掉别名可能造成真实缺陷漏报。

## 4. 三类敏感性：三个相互独立的精度轴

“敏感”表示分析保留某类区分；“不敏感”表示为了效率把它们合并。三个维度可任意组合，不应理解为线性等级。

## 4.1 流敏感性：区分程序点

**流不敏感（flow-insensitive）**分析通常为整个过程或程序计算一份全局事实，不区分语句顺序。

**流敏感（flow-sensitive）**在不同程序点保存不同状态，并沿 CFG 传播。

```c
p = &a;        // L1
p = &b;        // L2
use(*p);       // L3
```

流敏感分析可得：

\[
pts_{L1^+}(p)=\{a\},\qquad pts_{L2^+}(p)=pts_{L3}(p)=\{b\}
\]

典型流不敏感包含式分析则得到全局结果：

\[
pts(p)=\{a,b\}
\]

材料用 `x=3; x=5` 说明顺序差异，直觉正确，但那是值分析例子而非指针分析本身。另需注意：流敏感不等于永远执行“强更新”。只有能证明左值对应唯一具体位置时，旧事实才可被覆盖；对汇总堆对象往往只能弱更新，即把新旧事实合并。

## 4.2 上下文敏感性：区分函数调用实例

```c
int *id(int *x) { return x; }
p = id(&a);     // call site c1
q = id(&b);     // call site c2
```

上下文不敏感分析把两次 `id` 的形参与返回事实合并，可能得到：

\[
pts(p)=pts(q)=\{a,b\}
\]

上下文敏感分析区分两个调用上下文，可得到：

\[
pts(p)=\{a\},\qquad pts(q)=\{b\}
\]

“上下文”不只有完整调用路径；完整路径可能无限。常见有限抽象包括：

- \(k\)-call-site / call strings：保留最近 \(k\) 个调用点；
- object sensitivity：以接收者分配上下文区分面向对象方法；
- type sensitivity；
- functional approach / summary：为输入抽象状态计算摘要；
- heap cloning：同时按上下文区分堆对象。

仅把函数调用区分开而仍共享堆抽象，可能无法获得预期精度；上下文敏感性需说明“方法、参数、返回值、堆”分别如何上下文化。

## 4.3 路径敏感性：保留分支谓词相关性

```c
x = 0;
if (a > 0) x = 1;
else       x = 2;
if (a > 0) x += 3;
```

若在第一次 `if` 后把状态直接合并为 \(x\in\{1,2\}\)，第二次条件中又不记得它和第一次是同一谓词，可能产生伪值 \(5\)。路径敏感分析保留关联：

- \(a>0\)：`x=1` 后执行 `x+=3`，最终 `x=4`；
- \(a\le0\)：`x=2` 且不执行加法，最终 `x=2`。

所以 `x` **不可能**为 5，而不仅是“不总是等于 5”。

路径敏感不等于无限枚举每条完整路径。常见实现使用：

- 路径谓词与 SMT 求解；
- trace partitioning；
- BDD/决策图；
- 有界路径展开；
- 在选定位置进行状态合并。

若工具只做有界模拟而没有对未探索循环进行 sound 摘要，则结果通常是欠近似或不完备探索，不能仅凭“路径敏感”声称已覆盖所有行为。

## 5. Andersen 包含式指针分析

## 5.1 算法定位

经典 Andersen 分析是**基于约束、包含式（inclusion-based）**的 may-points-to 分析。典型教学版本具有：

- 流不敏感；
- 上下文不敏感；
- 路径不敏感；
- 单调增加 points-to 集合，不做删除；
- 通过最小不动点求解约束。

这些是常见实例配置，不是“Andersen”一词不可改变的定义。研究和工业实现可加入字段、上下文、类型过滤、增量求解等扩展。

与 Steensgaard 的合并式（unification-based）分析相比，Andersen 用集合包含约束，通常更精确但代价更高。

## 5.2 四类核心约束

设 `p`、`q` 为指针节点，`o` 为抽象对象。四类核心语句及约束如下。

### 5.2.1 Address：取地址

```c
p = &o;
```

约束：

\[
\{o\}\subseteq pts(p)
\]

这是 points-to 事实的种子。

### 5.2.2 Copy：指针复制

```c
q = p;
```

约束：

\[
pts(p)\subseteq pts(q)
\]

约束图可记为 `p --copy--> q`。材料用 `q ←Copy— p` 表示相同方向，但实现时必须统一“箭头表示赋值目标”还是“信息传播方向”。

### 5.2.3 Load：经指针读取指针值

```c
q = *p;
```

约束：

\[
\forall o\in pts(p):\quad pts(o)\subseteq pts(q)
\]

当发现新对象 \(o\in pts(p)\) 时，可动态加入 copy 边：

```text
o --copy--> q
```

这里把内存对象节点 `o` 也视作可保存 points-to 集合的抽象位置。

### 5.2.4 Store：经指针写入指针值

```c
*p = q;
```

约束：

\[
\forall o\in pts(p):\quad pts(q)\subseteq pts(o)
\]

当发现 \(o\in pts(p)\) 时，动态加入：

```text
q --copy--> o
```

在流不敏感 may 分析中这是弱更新：只增加 `pts(o)`，不会杀死旧指向。

## 5.3 字段敏感扩展：GEP/field

字段不敏感分析可能把 `o.left` 与 `o.right` 合并成整个对象 `o`。字段敏感分析引入字段对象：

\[
field: Obj^\#\times Field\to Obj^\#
\]

对：

```c
q = &p->f;
```

或 LLVM 风格的 `getelementptr`，有：

\[
\forall o\in pts(p):\quad field(o,f)\in pts(q)
\]

也可写成：

\[
field_f(pts(p))\subseteq pts(q)
\]

材料表格实际列出五行：Address、Copy、Load、Store 和 GEP/field。称“四类约束”时，通常指前四类核心内存约束；GEP 是字段敏感扩展的字段变换，而不是应被遗漏的普通复制。

字段敏感也不是自动精确：

- union、指针算术和强制类型转换可能让字段重叠；
- 数组下标可能被汇总；
- 一个分配点仍可能代表多个动态对象；
- LLVM GEP 计算地址，不执行内存读取，必须与 `load` 区分。

## 5.4 约束图

可将指针节点、对象节点作为图节点：

- Address 产生初始集合；
- Copy 是静态传播边；
- Load/Store 是依赖 `pts(p)` 才能实例化的条件边；
- GEP 把对象转换为字段对象后传播。

求解目标是满足全部包含约束的**最小解**。由于初始为空且只做并集传播，迭代从 \(\bot\) 上升，最终得到最小不动点，而不是任意满足约束的大集合。

## 6. 工作列表求解 Andersen 约束

## 6.1 数据结构

```text
pts[n]            每个节点的 points-to 集合
copySucc[n]       从 n 出发的 Copy 边目标
loadsFrom[p]      形如 q = *p 的 q 列表
storesThrough[p]  形如 *p = q 的 q 列表
gepsFrom[p]       形如 q = &p->f 的 (f,q) 列表
worklist          points-to 集合刚增长的节点
inQueue           可选：避免重复入队
```

高效实现还会维护 delta，即自上次处理后新增的对象，只传播增量。

## 6.2 初始化

对每条 Address 约束 `p=&o`：

```text
if o not in pts[p]:
    pts[p].add(o)
    enqueue(p)
```

Copy、Load、Store、GEP 关系先登记到相应邻接表。只有 points-to 集合发生新增才需要传播；“有 Address 入边的所有节点入队”只是实现这一原则的一种方式。

## 6.3 主循环伪代码

```text
while worklist not empty:
    n = pop(worklist)
    delta = newlyAdded(n)

    # 1. 沿静态/动态 Copy 边传播
    for dst in copySucc[n]:
        if pts[dst] union= delta changed:
            enqueue(dst)

    # 2. n 作为被解引用的基指针：q = *n
    for q in loadsFrom[n]:
        for o in delta:
            if addCopyEdge(o, q):
                # 新边必须传播源节点已有的全部事实
                if pts[q] union= pts[o] changed:
                    enqueue(q)

    # 3. n 作为被解引用的基指针：*n = q
    for q in storesThrough[n]:
        for o in delta:
            if addCopyEdge(q, o):
                if pts[o] union= pts[q] changed:
                    enqueue(o)

    # 4. 字段地址/GEP
    for (f, q) in gepsFrom[n]:
        for o in delta:
            of = field(o, f)
            if of not in pts[q]:
                pts[q].add(of)
                enqueue(q)
```

新 Copy 边加入时有两种正确策略：立即把源节点全部 `pts` 传播到目标，或把源节点重新入队并确保它会沿新边传播**已有事实**。若实现只传播“新增 delta”，简单重入队却不恢复历史 delta，可能漏掉结果。

## 6.4 为什么会终止

若抽象节点集合有限，则所有事实来自有限集合：

\[
PtsState=(Ptr\cup Obj^\#)\to\mathcal P(Obj^\#)
\]

每次有效更新至少加入一个从未出现的 `(node, object)` 对，且从不删除。因此最多加入有限多个事实，工作列表最终为空。此时：

- 没有新 points-to 事实；
- 没有尚未处理的新 Load/Store 实例化边；
- 所有 Copy/GEP 传播都稳定；
- 达到约束系统的最小不动点。

## 6.5 实现精度与效率注意点

- 用 bitset 表示集合，可显著加速并集与差集；
- SCC 压缩可合并等价传播结构，但合并条件必须保守；
- 类型过滤可提速，但错误过滤会损害 soundness；
- 分配点和字段对象的编号方式决定堆抽象精度；
- 间接调用会与指针分析互相依赖，常需迭代构建调用图；
- C/C++ 的指针算术、union、整数转指针、外部函数和未定义行为必须显式制定模型。

# 第二部分：抽象解释

## 7. 从具体语义到抽象语义

设具体状态集合为 \(\Sigma\)。一个状态可包含变量环境、堆、调用栈和程序计数器。程序在 CFG 边上的具体转移记为：

\[
F:\mathcal P(\Sigma)\to\mathcal P(\Sigma)
\]

直接枚举 \(\Sigma\) 往往无限或巨大。抽象解释选择抽象域 \(A\)，以抽象值代表一组具体状态：

\[
\alpha:\mathcal P(\Sigma)\to A,
\qquad
\gamma:A\to\mathcal P(\Sigma)
\]

- \(\alpha\)：把具体状态集合抽象化；
- \(\gamma\)：说明抽象元素代表哪些具体状态。

理想关系常写为 Galois connection：

\[
\alpha(S)\sqsubseteq a
\quad\Longleftrightarrow\quad
S\subseteq\gamma(a)
\]

抽象转移 \(F^\#:A\to A\) 若满足：

\[
F(\gamma(a))\subseteq\gamma(F^\#(a))
\]

则它对具体后继是 over-approximate 的。这里的“安全/sound”必须相对于这个包含关系与查询方向解释，而非泛指工具绝不会误报。

抽象域不要求一定有限。区间域就是无限高度域；关键是它应支持所需顺序、join、转移和终止策略。

---

## 8. 偏序、格与完备格

## 8.1 偏序

集合 \(A\) 上的关系 \(\sqsubseteq\) 是偏序，当它满足：

1. 自反：\(x\sqsubseteq x\)；
2. 反对称：\(x\sqsubseteq y\land y\sqsubseteq x\Rightarrow x=y\)；
3. 传递：\(x\sqsubseteq y\land y\sqsubseteq z\Rightarrow x\sqsubseteq z\)。

在程序分析中，\(x\sqsubseteq y\) 通常读作“\(x\) 比 \(y\) 更精确”或“\(x\) 表示的具体状态包含于 \(y\)”：

\[
x\sqsubseteq y\Rightarrow\gamma(x)\subseteq\gamma(y)
\]

## 8.2 上界、最小上界与 join

对 \(X\subseteq A\)，若所有 \(x\in X\) 都满足 \(x\sqsubseteq u\)，则 \(u\) 是上界。最小上界 \(\bigsqcup X\) 还满足：对任何上界 \(u\)，都有 \(\bigsqcup X\sqsubseteq u\)。

二元 join：

\[
x\sqcup y=\bigsqcup\{x,y\}
\]

它是同时覆盖两者的最精确抽象元素。控制流合流通常使用 join。

对偶地，最大下界/meet 为：

\[
x\sqcap y=\bigsqcap\{x,y\}
\]

## 8.3 格与完备格

- 任意两个元素都有 join 和 meet：格（lattice）；
- 任意子集都有 join 和 meet：完备格（complete lattice）；
- \(\bot=\bigsqcup\varnothing\) 是最小元素，通常表示无可达具体状态；
- \(\top=\bigsqcap\varnothing\) 是最大元素，通常表示完全未知。

## 8.4 幂集格

给定有限集合 \(U=\{0,1,2,3\}\)：

\[
(\mathcal P(U),\subseteq,\cup,\cap,\varnothing,U)
\]

是完备格。例如：

\[
\{0,1\}\sqcup\{1,2\}=\{0,1,2\}
\]

\[
\{0,1\}\sqcap\{1,2\}=\{1\}
\]

points-to 域正可建模为 \(\mathcal P(Obj^\#)\)。

格高度的计数有两种惯例：若按严格上升边数，有限幂集格高度为 \(|U|\)；若按最长链包含的节点数，则为 \(|U|+1\)。只写“高度等于元素数”而不说明惯例会产生一位差异。

## 9. 两个典型数值抽象域

## 9.1 符号域

### 9.1.1 完整符号幂集域

令基本符号类别：

\[
Sgn=\{-,0,+\}
\]

可用幂集格：

\[
A_{sign}=\mathcal P(Sgn)
\]

其中：

- \(\bot=\varnothing\)：不可达/没有具体整数；
- \(\top=\{-,0,+\}\)：任意整数；
- \(\{+\}\)：正数；
- \(\{0,+\}\)：非负数。

具体化例如：

\[
\gamma(\{+\})=\{z\in\mathbb Z\mid z>0\}
\]

join 是符号类别并集，meet 是交集。

### 9.1.2 五点简化域不是同一个域

很多教材使用：

\[
\{\bot,Neg,Zero,Pos,\top\}
\]

它不包含“非负”“非正”“非零”等中间元素，因此比完整幂集符号域粗。两种表示都可用，但不能一边声称域只有五个元素，一边又使用 `{0,+}` 作为合法元素。

### 9.1.3 抽象运算

抽象加法必须覆盖所有具体组合，例如：

\[
Pos+Pos=Pos,
\qquad Neg+Neg=Neg,
\qquad Pos+Neg=\top
\]

除零分析应把“除数可能为零”作为异常信息建模，不能把分析器的 \(\top\) 与语言值 `undefined` 混为一谈。

## 9.2 区间域

区间元素为：

\[
Intv=
\{[l,h]\mid
l\in\mathbb Z\cup\{-\infty\},
\ h\in\mathbb Z\cup\{+\infty\},
\ l\le h\}
\cup\{\bot\}
\]

具体化：

\[
\gamma([l,h])=\{z\in\mathbb Z\mid l\le z\le h\},
\qquad
\gamma(\bot)=\varnothing.
\]

偏序按包含关系：

\[
[l_1,h_1]\sqsubseteq[l_2,h_2]
\Longleftrightarrow
l_2\le l_1\land h_1\le h_2
\]

因此 \([0,0]\sqsubseteq[0,1]\)。

join 不是一般集合并本身，而是包含并集的最小区间，即凸包：

\[
[l_1,h_1]\sqcup[l_2,h_2]
=
[\min(l_1,l_2),\max(h_1,h_2)]
\]

例如：

\[
[3,8]\sqcup[7,12]=[3,12]
\]

meet 是区间交；若不相交则为 \(\bot\)：

\[
[3,8]\sqcap[7,12]=[7,8]
\]

\[
[0,1]\sqcap[3,4]=\bot
\]

区间域适合范围、数组下标、循环计数和部分溢出检查，但会丢失不连续集合与变量间关系。例如 `{0,2}` 被抽象为 `[0,2]` 后额外包含 1；约束 `x==y` 也无法由两个独立区间表达。八边形、polyhedra 等关系域可保留更多变量关系，代价更高。

若分析机器整数而非数学整数，还必须建模有符号溢出、无符号模运算及语言未定义行为；直接使用 \(\mathbb Z\) 区间不总是正确。

## 10. 抽象状态、程序点不变量与转移函数

设变量集合为 \(V\)，值域为 \(A_{val}\)。一个抽象状态是：

\[
State^\#=V\to A_{val}
\]

例如：

```text
{ a ↦ [0,0], b ↦ [1,1] }
```

若程序含堆，状态通常还包括：

```text
Environment#: Variable → AbstractValue
Store#:       AbstractLocation → AbstractValue
```

所谓“抽象轨迹”更准确地说常是程序点不变量映射：

\[
Inv:L\to State^\#
\]

或展开为：

\[
Inv:L\times V\to A_{val}
\]

它不是一条具体执行轨迹，而是在每个程序点汇总所有被分析执行的抽象状态。

### 10.1 \(\bot\) 不是“尚未赋值”

若 `b` 尚未初始化，不能简单令 `b ↦ ⊥`，因为状态域中的 \(\bot\) 通常表示“该程序点不可达/没有具体状态”。未初始化是一个真实可达状态，应使用：

- 独立元素 `Uninit`；
- 产品域 `Interval × InitStatus`；
- 或把值抽象为 `Uninit ∪ IntValue`。

混用二者会让分析错误地把可达路径当成不可达。

### 10.2 语句转移

对赋值 `a=0`：

\[
F^\#_{a:=0}(s)=s[a\mapsto[0,0]]
\]

对 `a++`：

\[
F^\#_{a++}(s)(a)=s(a)+[1,1]
\]

对真分支 `a<10`，可做 guard refinement：

\[
Guard^\#_{a<10}(s)(a)=s(a)\sqcap[-\infty,9]
\]

假分支则交 \([10,+\infty]\)。这种筛选是区间域上的最佳或近最佳抽象操作之一。

## 11. 循环与最小不动点

考虑：

```c
L1: a = 0;
L2: while (a < 10) {
L3:     a++;
    }
L4: use(a);
```

设 \(X\) 为循环头 `L2` 的区间不变量。入口贡献 `[0,0]`，回边贡献来自真分支和自增：

\[
\Phi(X)
=
[0,0]\sqcup\big((X\sqcap[-\infty,9])+[1,1]\big)
\]

循环头要解方程：

\[
X=\Phi(X)
\]

从 \(\bot\) 开始做 Kleene 迭代：

\[
X_0=\bot,
\qquad
X_{n+1}=\Phi(X_n)
\]

得到上升链：

```text
⊥ → [0,0] → [0,1] → [0,2] → ... → [0,10]
```

于是最小不动点为：

\[
Inv(L2)(a)=[0,10]
\]

循环体 `L3` 的入口在真分支约束后为 `[0,9]`，执行 `a++` 后的回边值为 `[1,10]`。退出边满足 `a>=10`：

\[
[0,10]\sqcap[10,+\infty]=[10,10]
\]

所以在数学整数、无其他修改且循环确实按上述 CFG 执行的前提下：

```text
L1 后：a ∈ [0,0]
L2 头：a ∈ [0,10]
L3 后：a ∈ [1,10]
L4 入：a ∈ [10,10]
```

### 11.1 为什么讨论不动点而不是“把循环跑完”

静态分析处理的不是某次具体循环，而是所有迭代次数的可达状态。循环头的状态既来自入口，也来自回边，因此必须满足递归方程。单调函数在完备格上由 Knaster–Tarski 定理拥有不动点；从底部做 Kleene 迭代，在适当连续性/有限高度条件下可得到最小不动点。

### 11.2 迭代次数不是固定常数

材料称边界 10 时“第 12 次达到不动点”、边界 10000 时需要 10002 次。这取决于：

- 初始迭代是否计数；
- 按节点还是按轮次调度；
- 工作列表顺序；
- 是否把最后一次无变化检查算一轮。

正确结论是：朴素区间迭代的步数随常量边界线性增长；精确的“12/10002”不是算法无关事实。对小例子这未必不可接受，但无界增长循环会形成无限上升链而根本不终止。

## 12. Widening：用有限步跳过无限上升链

## 12.1 为什么需要 widening

区间域存在无限严格上升链：

\[
[0,0]\sqsubset[0,1]\sqsubset[0,2]\sqsubset\cdots
\]

因此只靠 join 的 Kleene 迭代不保证有限步收敛。widening（加宽）算子记为 \(\nabla\)，设计目标是让序列：

\[
y_0=x_0,
\qquad
y_{n+1}=y_n\nabla x_{n+1}
\]

在有限步稳定，同时保持结果覆盖旧值和新候选值。

## 12.2 标准区间 widening

对旧区间 \([l_1,h_1]\) 与新候选 \([l_2,h_2]\)：

\[
[l_1,h_1]\nabla[l_2,h_2]=[l',h']
\]

其中：

\[
l'=\begin{cases}
-\infty,&l_2<l_1\\
l_1,&l_2\ge l_1
\end{cases}
\qquad
h'=\begin{cases}
+\infty,&h_2>h_1\\
h_1,&h_2\le h_1
\end{cases}
\]

对底元素约定：

\[
\bot\nabla I=I,
\qquad
I\nabla\bot=I.
\]

等价的实现方式是：第一次出现非底候选时直接用该候选初始化，从下一次更新起才应用普通区间 widening。

例如：

\[
[0,0]\nabla[0,1]=[0,+\infty]
\]

它看到上界增长，直接猜测可能继续增长到无穷，因此很快稳定，但丢失真实上界 10。

## 12.3 在哪里应用

通常只在 CFG 的循环头、回边目标或反馈顶点集合上使用 widening，而不是每条边都用。循环头方程变成类似：

\[
X_{n+1}=X_n\nabla\Phi(X_n)
\]

实现中常采用：

- 延迟 widening：先做若干轮普通 join；
- widening with thresholds：阈值包含 `0、10` 等程序常量，不立即跳到无穷；
- 分阶段 widening；
- 只在选定循环头 widening。

这些策略能显著改善精度，但必须仍保证最终终止。

## 12.4 示例的 widening 结果

使用朴素区间 widening，循环头很快变成：

\[
Inv_W(L2)(a)=[0,+\infty]
\]

真分支约束后再自增：

\[
([-\infty,9]\sqcap[0,+\infty])+[1,1]=[1,10]
\]

退出边：

\[
[0,+\infty]\sqcap[10,+\infty]=[10,+\infty]
\]

因此 widening 后：

```text
L2: [0,+∞]
L3 后: [1,10]
L4: [10,+∞]
```

这些区间仍为 sound 过近似，但比不加宽得到的 `[0,10]` 和 `[10,10]` 粗。

## 13. Narrowing：在加宽后恢复精度

## 13.1 基本思想

widening 稳定后得到后不动点 \(Y_0=X_W\)，满足：

\[
\Phi(Y_0)\sqsubseteq Y_0.
\]

在 \(\Phi\) 单调的前提下，narrowing 阶段从该后不动点开始，并仅在候选满足 \(\Phi(Y_n)\sqsubseteq Y_n\) 时执行：

\[
Y_{n+1}=Y_n\triangle\Phi(Y_n),
\qquad
\Phi(Y_n)\sqsubseteq Y_{n+1}\sqsubseteq Y_n.
\]

该下降条件以及 narrowing 算子的契约共同保证结果仍覆盖具体语义。narrowing 不保证恢复最小不动点，也不是所有分析都必须使用；其目标是在保持 soundness 的前提下，有限步移除一部分 widening 引入的无穷边界。

## 13.2 标准区间 narrowing

对旧区间 \([l_1,h_1]\) 和满足 \([l_2,h_2]\sqsubseteq[l_1,h_1]\) 的更精确候选 \([l_2,h_2]\)：

\[
[l_1,h_1]\triangle[l_2,h_2]=[l',h']
\]

其中：

\[
l'=\begin{cases}
l_2,&l_1=-\infty\\
l_1,&\text{otherwise}
\end{cases}
\qquad
h'=\begin{cases}
h_2,&h_1=+\infty\\
h_1,&\text{otherwise}
\end{cases}
\]

对底元素可约定：

\[
I\triangle\bot=\bot,
\qquad
\bot\triangle\bot=\bot.
\]

在要求“新候选不大于旧值”的前提下，\(\bot\triangle I\) 且 \(I\ne\bot\) 不会作为合法调用情形出现。

例如：

\[
[0,+\infty]\triangle[0,10]=[0,10]
\]

对本例，代回原方程：

\[
\Phi([0,+\infty])
=
[0,0]\sqcup([0,9]+[1,1])
=[0,10]
\]

一次区间 narrowing 即可将循环头收缩为 `[0,10]`，随后退出状态成为 `[10,10]`。

## 13.3 工程注意事项

- narrowing 应在 widening 阶段稳定后开始；
- 常只做固定少量轮次，避免复杂域上的高成本或不稳定；
- “重新应用原始分析”是直观解释，严格实现还需要定义 narrowing 算子或保证下降序列的性质；
- 恢复到精确结果是本例特性，不是一般保证；
- “总共只需 5 次”依赖具体调度、延迟策略和计数方式，不是 widening/narrowing 的普遍复杂度结论。

## 14. 把 Andersen 放回抽象解释框架

Andersen 的状态可写为：

\[
A_{pts}=(Node\to\mathcal P(Obj^\#),\sqsubseteq)
\]

其中逐点偏序：

\[
S_1\sqsubseteq S_2
\Longleftrightarrow
\forall n:\ S_1(n)\subseteq S_2(n)
\]

- \(\bot\)：所有节点的 points-to 集合为空；
- join：逐节点集合并；
- Address/Copy/Load/Store/GEP：单调抽象转移；
- worklist：不动点迭代调度器；
- 有限抽象对象集合：保证格高度有限，因此无需 widening 也会终止。

这揭示两部分内容的统一性：

| 指针分析术语 | 抽象解释视角 |
|---|---|
| 抽象对象 | 具体内存位置集合的抽象表示 |
| `pts(p)` | 幂集格中的抽象值 |
| 包含约束 | 单调抽象语义方程 |
| Copy 传播 | 抽象转移 |
| CFG/调用图位置 | 状态索引维度 |
| 工作列表 | 不动点求解策略 |
| 流/上下文/路径敏感 | 对程序点、调用历史、谓词的抽象划分 |
| 字段敏感 | 对内存对象维度的更细分区 |

精度提升本质上常是把原本合并的具体状态拆到更多抽象元素中；代价是域更大、迭代更多、内存更高。

## 15. 原文易误解或技术错误（集中纠正）

1. **Pointer analysis、points-to analysis 与 alias analysis 不宜直接视为同义词**：前者通常计算指针到抽象对象的集合映射，alias 查询由集合及额外语义派生。
2. **points-to 对象不限于“地址被取过的变量”**：还包括堆分配点、字段、数组区域、函数和其他抽象位置。
3. **集合有交集只支持 may-alias 候选**：在过近似结果中可能是伪别名，不能据此断言某次真实执行一定别名。
4. **单元素相同 points-to 集合不总能推出 must-alias**：分配点汇总对象可能代表多个动态实例，还需处理 null、生命周期与同时可达性。
5. **流敏感示例实际是值分析**：`x=3; x=5` 能解释顺序，但没有展示指针 points-to 的更新；正文已换成指针例子。
6. **流敏感不自动意味着强更新**：对可能代表多个位置的抽象对象只能弱更新。
7. **上下文敏感不等于保存完整调用路径**：实际多用有限 call string、object sensitivity 或函数摘要；还需说明堆是否上下文化。
8. **路径敏感不等于枚举所有路径**：可通过谓词分区、SMT 和有限状态拆分实现；有界探索若无 sound 摘要不能证明未探索行为安全。
9. **路径示例结论措辞错误**：问题是“x 是否会等于 5”，精确答案是“不可能等于 5”，而不是“不总是等于 5”。
10. **YASA 的有界模拟与 soundness 需分开说明**：牺牲循环深层展开可能造成欠近似；只有对截断部分做保守摘要时才能支持相应安全保证。
11. **Andersen 的三种不敏感性是经典配置，不是所有扩展的硬性定义**：字段敏感、上下文敏感或增量变体均存在。
12. **字段敏感表实际有五行操作**：四类核心约束是 Address/Copy/Load/Store，GEP/field 是字段对象变换扩展，应单独解释而非塞进普通 Copy。
13. **LLVM `getelementptr` 不读取内存**：它计算派生地址；真正读取由 `load` 完成。
14. **约束边方向容易混乱**：`q=p` 的信息从 `p` 流向 `q`。文字箭头、图边和赋值符号必须统一。
15. **工作列表处理“入边/出边”的描述过于模糊**：正确触发依据是哪个节点的 `pts` 新增，以及该节点作为 Copy 源或 Load/Store 基指针的角色。
16. **新 Copy 边不能只让源节点机械重入队**：增量实现必须确保源节点历史 points-to 事实也沿新边传播，否则会漏解。
17. **抽象解释不要求把无限具体值映射到有限抽象域**：区间域本身无限；widening 用于处理无限高度。
18. **“保证安全性”缺查询方向**：抽象转移的 soundness 是具体后继被抽象后继覆盖；告警仍可能误报。
19. **格的 join/meet 原定义有误**：`x⊔y` 是集合 `{x,y}` 的最小上界，不是“x 的最小上界与 y 的最小上界”。
20. **幂集格高度有计数约定差异**：按边数为 \(|U|\)，按链节点数为 \(|U|+1\)。
21. **符号域的两种版本被混用**：完整幂集域允许 `{0,+}`，五点域不允许；必须选定其一。
22. **区间 join 不等于一般集合并**：它是并集的最小区间凸包；不相交区间的 meet 应为 \(\bot\)。
23. **“未赋值变量 = \(\bot\)”错误**：\(\bot\) 通常表示程序点不可达；未初始化应是独立的可达抽象值。
24. **“抽象轨迹”容易让人误以为是一条路径**：材料中的 \(L\times V\to A\) 实质是程序点不变量映射，汇总了多条执行。
25. **循环头前驱描述有误**：第一次求值时回边尚为 \(\bot\)，但 CFG 中 `L2` 的结构前驱仍包括 `L1` 和 `L3`，不能说“只有一个前驱”。
26. **循环固定点迭代次数不是算法无关常数**：12、10002 依赖计数方式和调度；应陈述为随边界线性增长。
27. **区间算术默认数学整数**：分析 C/LLVM 机器整数时必须考虑溢出、`poison` 或未定义行为。
28. **widening 不只是“预测最终结果”**：其核心契约是产生覆盖候选的上界并使迭代序列有限稳定；预测趋势只是直觉。
29. **narrowing 不保证恢复精确最小不动点**：本例能恢复 `[0,10]`，一般程序和抽象域未必能。
30. **“widening+narrowing 仅 5 次”不是普遍结论**：轮数依赖 widening 点、延迟轮数、阈值、调度与 narrowing 策略。
31. **指针分析与污点传播是不同分析**：指针分析提供内存关系，污点分析在其上使用这些关系传播标签；不能说指针分析自身负责追踪所有敏感信息。
32. **“几乎所有抽象法分析都能由抽象解释理解”是合理视角，但安全证明并非自动获得**：仍需给出具体/抽象语义、抽象关系、单调性与局部 soundness 证明。
